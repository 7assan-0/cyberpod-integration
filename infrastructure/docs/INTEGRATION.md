# Integration handoff — proposed cyberpod.infra/v1

No existing Core runtime language or implemented Lab contract was available. This contract is an infrastructure adapter proposal for Astra #1 to review and map to its existing Lab schema; it does not redefine public Core endpoints. Requests contain resolved infrastructure only. Tasks, flags, scores and validation events stay with their owners.

## Astra #1 — required interface

Call the adapter from a trusted worker process, either with Python or through argv plus JSON stdin. Do not invoke it through a shell with interpolated request values. The installed CLI is `cyberpod-infra`; running `python3 -m cyberpod_infra` from `infra/` is equivalent and requires no install.

| Operation | Python method | CLI |
| --- | --- | --- |
| Start | `Engine.start(request)` | `start` + JSON stdin; optional `--wait` |
| Observe | `Engine.status(session_id)` | `status UUID` |
| Stop/destroy | `Engine.stop(session_id, expected_generation)` | `stop UUID --generation UUID` |
| Restart/reset | `Engine.restart(request, expected_generation)` | `restart --generation UUID` + JSON stdin |
| Wait for readiness | `Engine.wait(session_id, timeout)` | Included by `start/restart --wait` |
| Reconcile | `Engine.reap()` | `reap` |
| Validate contract | `validate_request(request)` | `validate` + JSON stdin |
| Render for review | `compose(validated_request, instance, generation)` | `render` + JSON stdin |

Construct Python adapters with `Engine(Policy.load('/etc/cyberpod-infra/worker.json'))`. `render` emits a Compose document referencing external networks and volumes; only the adapter creates those resources and installs required policy. Calling Compose up directly is not the supported start path.

Start/stop are idempotent within the documented lifecycle. The same Session UUID with the same normalized request returns existing state; changing a live request conflicts. A cleaned Session requires explicit restart or a new UUID. Restart requires the current generation, preserves Lab identity, destroys old resources before replacing them, and returns a new generation. Stop can accept an omitted generation for administrator recovery; Core must always pass it to prevent a delayed stop from deleting a restarted Session.

The input is a strict JSON object; `model.validate_request` is the authoritative executable schema. Unknown fields fail rather than being forwarded to Docker. `examples/make_request.py` emits a complete, current request.

| Field | Contract |
| --- | --- |
| `api_version` | Exact `cyberpod.infra/v1` |
| `session_id` | Canonical lowercase UUID generated by Core |
| `lab_id` | Catalog identifier; lowercase letters, digits, hyphen; starts with a letter |
| `expires_at` | UTC Unix epoch seconds, in the future and within worker max TTL; immutable for idempotent start |
| `startup_timeout_seconds` | 10–600; default 120 |
| `network` | `internet`: `none`, `restricted`, `internet`; `allow`: array of `{cidr, protocol, port}` for restricted mode |
| `services` | 1–8 service objects described below |
| `volumes` | Optional array of `{id, size_mb, uid, gid}`; always session-owned bounded temporary memory volumes |

| Service field | Contract |
| --- | --- |
| `id` | Unique service/DNS identifier |
| `image` | Operator-allowlisted local image; production digest references required |
| `user` | Numeric nonzero `uid:gid`, such as `1000:1000` |
| `command` | Optional argv array; existing image entrypoint remains in effect |
| `environment` | Optional string-to-string mapping; `CYBERPOD_` keys are reserved |
| `resources` | `{cpus, memory_mb, pids, shm_mb}`; required |
| `tmpfs` | Optional `{path, size_mb, exec}` entries; exec defaults false; no arbitrary host paths |
| `volumes` | Optional `{volume, target, read_only}` mounts; read_only defaults false; copy-up disabled |
| `healthcheck` | `test: ['CMD', ...argv]`; optional interval/timeout/retries/start_period fields in seconds |
| `endpoints` | Optional `{name, port, protocol}`; protocol `http`, `https` or `tcp`; port 1024–65535; metadata only, never a host publish |

Limits are enforced both per service and against operator-configured aggregate budgets. See validation source for exact size/count ranges. Images cannot opt out of security settings. Shared Core must not contain a conditional for a particular Lab.

The adapter injects these non-secret per-service variables: `CYBERPOD_SESSION_ID`, `CYBERPOD_LAB_ID`, `CYBERPOD_SERVICE_ID`, `CYBERPOD_EXPIRES_AT`. Core may add generic Lab-owned values such as `TARGET_URL=http://target:8080` to a service's environment. Flag/session secret generation and target-only injection belong to Core's Lab/validator integration, not this adapter. Never inject answers into a desktop environment or student-visible metadata.

Responses contain `api_version`, `instance`, `session_id`, `lab_id`, `generation`, `status`, `created_at`, `expires_at`, `error`, `cleanup_errors`, `resources`, `budget`, `network`, `services` and `endpoints`. `resources` groups concrete container IDs, network IDs and volume names. Service observations expose only container ID, health state, running state, IP and OOM indicator. Env values, flags, health logs, raw Docker errors and Compose contents are excluded.

On READY, each endpoint has `name`, `service_id`, `protocol`, `address`, `port`, and `scope: 'worker-host-only'`. These are private routing records for the trusted worker proxy. They are not browser URLs, public ports or credentials, and they change after restart. Other states have an empty endpoint list.

| Infra state | Meaning | Suggested Core handling |
| --- | --- | --- |
| `STARTING` | Resources created, readiness incomplete | Core STARTING; do not expose workspace yet |
| `READY` | Every expected application health check passed | Core RUNNING; authorize proxy route |
| `FAILED` | Health/deadline/runtime failure, resources may still exist | Core ERROR; revoke route and stop/reap |
| `STOPPING` | Cleanup intent persisted | Core STOPPING |
| `CLEANUP_FAILED` | Cleanup incomplete or daemon-timeout hold active | Keep capacity reserved; retry cleanup; surface operator error |
| `CLEANED` | No owned Docker resources and session policy/files removed | Core CLEANED; `error` may still explain a failed start or expiry |

A rolled-back failed start can return `status: CLEANED` with a non-null `error`; it is not a successful start. On pre-mutation errors the CLI emits `{api_version, error: {code, message}}`. Exit 0 means the requested operation has no reported failure; exit 1 means runtime/cleanup failure, exit 2 means invalid input or a known dependency/policy failure, exit 3 means an unexpected internal failure. A successful stop can preserve a prior failure code for diagnosis, so consumers must inspect both operation and state.

Error codes include `INVALID_REQUEST`, `INVALID_POLICY`, `DEPENDENCY_MISSING`, `HOST_UNSUPPORTED`, `CAPACITY_EXCEEDED`, `IMAGE_REJECTED`, `STATE_CONFLICT`, `NOT_FOUND`, `ORPHAN_RESOURCES`, `STATE_CORRUPT`, `FIREWALL_DRIFT`, `SANDBOX_MISMATCH`, `COMMAND_FAILED`, `COMMAND_TIMEOUT`, `CONTAINER_UNHEALTHY`, `CONTAINER_MISSING`, `NETWORK_MISSING`, `NETWORK_MISMATCH`, `RESOURCE_MISMATCH`, `STARTUP_TIMEOUT`, `SESSION_EXPIRED`, `WAIT_TIMEOUT`, `CLEANUP_FAILED`, `OWNERSHIP_MISMATCH`, `INTERNAL_ERROR`.

Core responsibilities remain: user/session authorization, catalog trust, request translation, worker assignment, generation tracking, expiration selection, public session-state mapping, backend calls, error presentation and authenticated/revocable desktop proxy routes. Install the independent reaper so backend/browser failure does not leave labs running indefinitely. No browser or student should call this root-authority worker interface directly.

## Astra #3 — Kali dependencies

Supply an image that can start as a numeric non-root user with a read-only root, zero additional capabilities and `no-new-privileges`. The worker does not modify XFCE, VNC or noVNC. The image must not declare Dockerfile `VOLUME`; put writable home/runtime paths in the request. Empty tmpfs homes must be initialized from baked-in defaults by an unprivileged entrypoint. Mounting `/run` or `/home/learner` hides baked-in data there.

Provide an exec-form readiness command that checks the actual desktop stack, including X/VNC/WebSocket readiness as appropriate; checking that the container or a static noVNC page exists is insufficient. Declare the noVNC HTTP/WebSocket service port in `endpoints`. Core/#5 must place authenticated routing in front of this private upstream. Avoid relying on published ports or a shared ingress bridge.

Default proposed desktop resources are 2 CPU, 2 GiB RAM, 256 PIDs and 128 MiB shared memory; measure them with the actual browser image. Chrome/Firefox sandbox compatibility must be tested under the host's seccomp configuration; do not silently add privileged mode or disable browser sandboxing. Raw-socket tools will not work in the strict profile; use TCP-connect workflows or submit a narrowly scoped capability request with tests.

Required deliverables from #3: immutable image reference, numeric user, command if needed, writable directories and sizes, full-stack health command, readiness time budget, endpoint port/protocol, and target URL/configuration environment contract.

## Astra #4 — Lab target dependencies

Supply the Lab-specific target image and the service/environment/data requirements. The target should bind to `0.0.0.0` on an unprivileged internal port, expose a real readiness check, and run with bounded temporary state. DNS names such as `target` are local to the Session; no fixed IP or global container name is required. Additional targets are additional service records within the Session's isolated network.

The optional `images/target-runtime/Dockerfile` is a Python infrastructure foundation with a non-root user and generic `/healthz` probe. It includes no scenario, login, credentials, flags or application CMD. Astra #4 can inherit it or supply any independently compatible image; using this base is not a requirement. Do not replace an existing target application with the harmless probe fixture.

Per-session training credentials/flags must be generated and validated by their owners and injected only into the intended target. Internal validation/events should use a reviewed route through Core; this strict profile intentionally does not grant targets broad control-plane connectivity. Any callback address requires a separately agreed least-privilege interface, not opening private-network egress globally. Reinitialization must work with empty volumes on each restart.

## Outstanding cross-team integration requests

1. Astra #1: map this adapter to the actual Lab schema and existing session/provider interface; confirm worker assignment, generation handling and failure-state mapping.
2. Astra #1/#3/#5: supply the authenticated host proxy, HTTP/WebSocket routing and per-session revocation contract.
3. Astra #3: confirm that Kali starts without root, extra capabilities, writable root or anonymous Dockerfile volumes; provide readiness and measured memory needs.
4. Astra #4/#6: agree on target-only secret injection and trusted validation event transport. No broad network exception or scoring changes are included here.
5. Astra #6: run the included real-host acceptance and then full Core → Kali → target → validator integration. Local unit tests do not establish end-to-end product readiness.

These are requested changes/dependencies, not edits to any other agent's component.
